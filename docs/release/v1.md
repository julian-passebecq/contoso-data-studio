# Contoso Data Studio v1: release, install, run, recover and roll back

Local-first synthetic retail data product: Python API (FastAPI, DuckDB, DuckLake, dbt-duckdb) plus a React and
Fluent UI interface. Everything runs on loopback; no cloud service, Fabric workspace or real business data is used.
All data is **synthetic**.

## What is in the release

| Area | Delivered |
| --- | --- |
| Retail product | Projects, Generate, Lakehouse, Transform, Query, Explore, Charts, Canvas, Apps (operational lab and Architecture) |
| Data pipeline | deterministic generator (scenario, seed, scale, file sha256), DuckLake Bronze, dbt Silver/Gold with data tests, snapshots and time travel |
| Workspaces | isolated named workspaces, remembered across restarts, backup zip and restore-as-new |
| Mosaic exports | Gold -> `datapass.artifact` v1 bundle plus lineage receipt and full Parquet; concept spec 1.0.0 architecture export |
| DataPass React | source-backed traces in `docs/datapass-react/` (checked by `check_traces.py`) |
| Rayfin boundary | declared Gold-to-app mapping and provenance on the app mirror (`docs/fabric-apps/GOLD-MAPPING.md`) |
| Qualification | API unit/integration tests, web unit tests, typecheck/build, dbt Charts validation, Rayfin model check, browser smokes and the real retail journey (`tools/qa_retail_journey.py`) |

## Install

Prerequisites: Python 3.11-3.13, Node.js 22 LTS (Node 26 works for the app and build; its built-in `localStorage`
breaks the jsdom unit tests, so run `npm test` on Node 22), Git. dbt Charts (`dct`) is optional.

```bash
git clone https://github.com/julian-passebecq/contoso-data-studio.git
cd contoso-data-studio
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -e "apps/api[dbt]"
npm --prefix apps/web install
```

## Run

```bash
uvicorn app.main:app --app-dir apps/api --host 127.0.0.1 --port 8000
npm --prefix apps/web run dev            # http://localhost:5173
```

Production bundle instead of the dev server: `npm --prefix apps/web run build` then
`npx --prefix apps/web vite preview --host 127.0.0.1` (it proxies `/api` the same way). The API binds to loopback;
do not expose it on a network interface: it has no authentication and is meant for one local user.

## Workspaces, backup and recovery (tested)

- Header **Workspace** -> **Manage** -> create, back up, restore. Named workspaces live in `workspaces/<id>/`
  (or `$CONTOSO_HOME/<id>/`), backups in `workspaces/_backups/<id>-<UTC>.zip`.
- A restore always creates a **new** workspace from the zip; existing workspaces are never overwritten. Archives
  with absolute paths, `..` segments or foreign layouts are rejected before anything is written.
- The backup holds the DuckLake catalog and data files, staging runs (with their sha256 manifests), imports,
  exports, dbt target and app-lab store. Run files are re-verified against their hashes when reopened.
- Tested by `apps/api/tests/test_workspaces_exports.py` (two workspaces, export, backup, restore, reopen) and by the
  journey (API restart reopens the remembered workspace and its Gold result).
- Manual route without the API running: copy the workspace folder somewhere safe; to restore, copy it back as a new
  folder under `workspaces/` with its `workspace.json`, or back into `workspace/` for the default workspace.

## Upgrade and roll back

- Upgrading keeps the existing `workspace/` folder in place as the **Default workspace**; nothing is moved or
  rewritten, and its browser history keys are unchanged.
- Before an upgrade, create a backup of every workspace you care about (Manage -> Back up).
- Roll back the code with `git checkout <previous tag or commit>` and reinstall (`pip install -e "apps/api[dbt]"`,
  `npm --prefix apps/web install`). Named workspaces are plain folders; an older version simply ignores
  `workspaces/` and keeps using `workspace/`.
- If a dbt model change breaks a build, the previous Gold tables stay in DuckLake; exports are refused until the
  model builds again (Transform shows the failing model and its diagnostics).

## Release qualification

Run on the exact commit you release:

```bash
pytest -q apps/api/tests
npm --prefix apps/web test && npm --prefix apps/web run build
python docs/datapass-react/check_traces.py
python tools/qa_retail_journey.py --mosaic <path to datapass-mosaicstudio>
```

CI (`.github/workflows/ci.yml`, `qa-browser.yml`) runs the same suites on Ubuntu, including the journey and the
Mosaic validator against the pinned `studio-v0.8.1` tag, and uploads the evidence.

## Not in this release

No Fabric, Databricks, Spark, Power BI/DAX or cloud deployment; Fabric runtime qualification is blocked by access
and not claimed. No desktop installer: the product is installed from source as above. The retail-to-app mapping in
the operational lab is declared but disabled until a product decision maps retail channels to app departments.
